# 《硅基经济学》写作风格规范

本书定位：15-20 万字严肃畅想集。专业深度打底、可读性做壳、偏向可读性。读者是对技术趋势感兴趣的普通知识人群，不是开发者，也不是经济学家。

写任何正文之前，先过一遍下面四组规则。写完之后，用文末的自查清单逐条检查。

## 一、去 AI 味（最高优先级）

AI 味不是玄学，是以下具体习惯的叠加。每一条都是硬约束：

### 1. 禁止对称排比结构
不要让连续的段落/要点长成同一个模子（如每段都是"提问→解释→这是第X章要讲的"）。真实写作是不对称的：有的问题啰嗦地展开，有的一句带过，有的用反问代替陈述，有的干脆合并。**故意打破对称。**

### 2. 数字要克制，留一个咬住，其余模糊
禁止"214 笔交易、1.86 美元、19 个服务商、7 个司法管辖区"这种数字堆砌——太多、太精确、都刚好服务论点，反而假。一段话里只留一个精确数字反复强调，其余用模糊表达："十几个服务商""小半个地球的司法管辖区"。不精确更像人话。

### 3. "不是A，而是B"全文限用一次
这是中文 AI 写作第一口癖。全章只允许出现一次，用在最有力的地方。其余全部改成：直接陈述、举反例、或不解释直接往下走。同类需警惕的口癖还有："换句话说""值得注意的是""更重要的是""某种意义上""本质上"。

### 4. 金句加粗每章最多两处
禁止每 200 字蹦一句可以印在海报上的加粗总结。一章内最多 1-2 处真正的加粗强调。其余"总结句"要么删，要么写得像随口一说，不要刻意打光。

### 5. 情绪曲线不能是平的
匀速、克制、"正在做严肃演讲"的调子是最大破绽。每章要有语气波动：偶尔自嘲、偶尔停顿、偶尔承认"这里我也不确定"、偶尔用口语化的吐槽打断论述。思考的毛边要留着。

### 6. 删掉伪精确的仪式感
"东部时间凌晨 3 点 17 分"里的"东部时间"就是伪精确。凡是为了显得郑重而添加、实际不承载信息的修饰，删。

### 7. 句子长短要有节奏
连续三个以上等长的句子就是机器节奏。长句后面跟短句。有时候一句话就是一段。

## 二、专业性：有底子，但不能是教科书

### 1. 概念只在需要时出现，出现时用场景带出
不要"定义先行"（"所谓X，是指……"是教科书写法）。让概念从一个具体场景里自然长出来，读者先看见现象，再获得名字。

### 2. 技术术语翻译原则
HTTP header、session token、JSON、API 网关这类词，正文中要么不用，要么用生活类比替换（402 响应 = 机器可读的报价单；session token = 一次性授信额度）。自查标准：**这一段能否讲给一个聪明但不写代码的朋友听懂？**

### 3. 专业深度体现在推演的严谨，不在术语的密度
经济学功底应该体现为：因果链条经得起推敲、反例考虑周全、承认不确定性。而不是引用大词（边际效用、科斯定理）来装饰。真要用经济学概念，用完要立刻付一个具体例子。

### 4. 数据和事实分层标注心态
写作时明确区分三类内容并在行文语气上体现差异：已发生的事实（2025 年 Coinbase 启用 X402）用确定语气；合理外推（微支付市场会长大）用推测语气；纯思想实验（2031 年的 Orion）明示虚构。混淆三者是严肃作品的死罪。

## 三、面向普通读者

### 0. 章节曲式：动笔前先声明，相邻章节不得同型
单章质量靠下面的规则，全书质量靠章节形态的变化——五章连读全是"历史轶事→论点→案例→泼冷水→下集预告"，句子再好也是模板。动笔前先声明本章曲式，且不得与上一章相同。可选曲式（不穷举）：
- **历史类比型**：一个历史对应物贯穿全章（第 1-4 章的默认型，已连用四次，慎用）
- **单案例深潜型**：一个案例从头讲到尾，分析嵌在叙事里（第七章"Agent 的一天"天然是这型）
- **辩论型**：开场摆出最强对立观点，全章正反交锋，作者最后才亮牌（适合争议章节，如第十、十一章）
- **拆解型**：结论先行，然后层层拆开论证
- **文档型**：用虚构的 Agent 日志、审计报告、监管函件等"材料"串起一章
度的把握是"七分稳三分变"：每部分（2-3 章）允许一章非标准曲式，其余做基本型的变奏，不必章章求新。

### 1. 开篇必须"具体先于抽象"，但手法必须轮换
读者先"看到"再"理解"——这是原则，不变。但"历史场景开场"只是实现它的一种手法，连用就成了新模板。可用手法包括：历史场景、虚构叙事（Orion 线）、反常识提问、一段对话或争论、当下新闻、数据反差、直接抛争议论点（偶尔违反"先具体"规则本身就是人味）。**同一开场手法不得连用两章**，用前查文末的"开场手法登记表"并在用后登记。

### 2. 一章只推一个核心观点
其余都是这个观点的展开、例证、反驳与回应。读者合上书能用一句话复述本章，就成功了。

### 3. 类比优先于解释
"X402 是互联网的集装箱"胜过三段机制描述。但类比要新鲜，禁止陈词滥调（"就像高速公路""就像水电煤"）。

### 4. 假设读者聪明但不耐烦
不解释常识（什么是 App Store），不重复已讲过的内容（前章讲过的概念直接用），但任何新概念出现必须当场给够上下文。

## 四、趣味性

### 1. 结尾：禁止总结，钩子形态要轮换
唯一硬禁令：不许用"总而言之"式段落复述本章观点。"下集预告"式钩子是好手法但已成惯性（前五章全是），可选的结尾形态还有：戛然而止在一个反例上、用一段虚构片段收尾、回扣本章开头（环形结构）、留一个作者自己也答不了的问题、冷幽默收尾。连续两章不得用同一种结尾形态。

### 1.5 反方观点的位置要游动
每章必须诚实处理最强反例，但位置不限。固定在章节 80% 处"泼冷水"是模板感的重要来源。可以开场就抛最强反对意见、全章都在回应它；也可以把冷水拆碎洒在各处；也可以留到结尾戛然而止。

### 2. 拟人与幽默有配额
Agent 可以拟人化叙事（Orion 的故事线可贯穿全书），冷幽默和自嘲每章可以有几处，但不做段子手——趣味为理解服务，不为取乐服务。

### 3. 用"信息差"制造张力
"她自己还不知道——知道这件事的是她的 Agent"这种写法优于平铺直叙。人类角色不知道而读者知道的事，是本书天然的戏剧资源（硅基经济对人类"不可见"正是全书主题之一）。

### 4. 虚构片段的克制使用
虚构场景（未来新闻、Agent 日志）是调味料不是主菜。每章至多一处集中的虚构叙事，其余篇幅回到分析与推演。

## 写完后的自查清单

逐条检查，任何一条不过就返工：

- [ ] 全文"不是……而是……"出现 ≤ 1 次
- [ ] 加粗金句 ≤ 2 处
- [ ] 没有连续两段结构对称
- [ ] 每段精确数字 ≤ 1 个
- [ ] 有至少 2 处语气波动（自嘲/存疑/口语吐槽）
- [ ] 技术术语全部通过"聪明朋友测试"
- [ ] 事实/外推/虚构三种语气分明
- [ ] 开篇具体先于抽象，且开场手法与上一章不同（查登记表）
- [ ] 本章曲式与上一章不同
- [ ] 结尾没有总结本章，且结尾形态与上一章不同
- [ ] 反方观点的位置和上一章不在同一处
- [ ] 朗读一遍：有没有哪句是"你本人绝不会这么说话"的？有就改
- [ ] 写完后更新文末登记表
